# 测试策略

EasyMotion 当前采用两类测试：主进程与集成逻辑使用独立 Node.js 脚本；Renderer 纯 TypeScript 逻辑使用 `tsx + node:test`，直接导入生产源码。类型检查由 `tsc` 单独负责。

## 日常门禁

在仓库根目录运行：

```bash
pnpm check
```

它依次执行：

1. `pnpm lint`：ESLint，禁止 warning。
2. `pnpm typecheck`：检查 Renderer 源码和 TypeScript 测试。
3. `pnpm test`：运行稳定、离线的核心回归测试。

默认测试包括项目与文件服务、timeline、Generator、Agent、Remotion Code Agent、视觉反馈、memory、预设、坐标、Renderer timeline 纯函数和 Remotion importer。`test-generator.js` 只在 m2 中执行一次；`test:m3` 仅保留为兼容旧命令的别名。

## 测试分层

| 命令 | 用途 | 默认门禁 |
| --- | --- | --- |
| `pnpm test` | 稳定、离线的核心回归 | 是 |
| `pnpm check` | lint + typecheck + 核心回归 | 是 |
| `pnpm test:release` | 导出工程与真实 Remotion 渲染 | 否，发布前运行 |
| `pnpm test:live` | 真实 LLM Agent 与 service flow | 否，手工运行 |
| `pnpm test:all` | 核心回归 + 发布测试，不含真实 LLM | 否 |

`test:release` 中的工程导出测试会在临时目录安装 Remotion 依赖，需要 npm 缓存或网络，因此不进入日常门禁。`test:live` 需要本地 API Key，可能产生费用且受网络和模型输出影响。

## Electron 子项目命令

以下命令在仓库根目录通过 `pnpm --filter @easymotion/electron <命令>` 调用，或在 `apps/electron/` 中直接运行：

| 命令 | 覆盖范围 |
| --- | --- |
| `test:m1` | 文件、项目、UI 状态、Workspace、窗口 IPC |
| `test:m2` | timeline schema、Generator、预览与时间计算 |
| `test:m5` | 对话、LLM、Agent tools、素材、预设、撤销与异常恢复 |
| `test:m5.2` | Remotion Code Agent、沙箱、registry 与 router |
| `test:m8` | 导出预检、工作区、工程 ZIP |
| `test:m11` | Remotion native render、帧渲染、截图、视觉反馈 |
| `test:m11:real-render` | 真实 Remotion 渲染 |
| `test:m12` | Agent memory 服务、设置、工具和上下文 |
| `test:renderer` | Renderer timeline 属性与 transform 纯函数 |
| `test:presets` | preset 同步、查询、参数与放置 |
| `test:importer` | Remotion manifest、AST 与同步恢复 |

## 新增测试规则

- 修 bug 时增加能复现问题的回归测试。
- 测试必须调用生产实现；禁止在测试文件里复制一份待测算法。
- 稳定、离线、无外部副作用的测试加入 `test:core`。
- 会下载依赖、执行真实渲染或明显较慢的测试加入 `test:release`。
- 需要 API Key、会产生费用或依赖模型输出的测试加入 `test:live`。
- 临时文件必须写入系统临时目录，并在成功或失败后清理。
- 不因为测试失败而删除测试；先确认是产品回归、需求变化还是测试夹具过时。

测试文件当前保留在 `apps/electron/tests/`，不为目录美观进行无收益的批量迁移。Renderer TypeScript 测试放在 `apps/electron/tests/renderer/`。
